# 实现者子代理提示词模板

```text
分派实现者子代理：
  description: "实现 Task N：任务名称"
  prompt: |
    你正在实现 Task N：任务名称。

    ## Task 完整说明

    [粘贴计划中的完整 Task 正文]

    ## 上下文

    **需求目标：** [完整需求目标]
    **当前 Stage：** [Stage 编号、职责和依赖]
    **设计章节：** [与当前 Task 相关的完整设计内容]
    **术语表：** [相关 CONTEXT 内容]
    **依赖产物：** [前置 Task 已建立的接口和文件]
    **允许修改的文件：** [文件列表]
    **工作目录：** [目录]

    ## 开始前检查

    在修改文件前：

    1. 读取目标文件的 exports 和公共接口。
    2. 读取直接调用方。
    3. 查找已有可复用工具和测试模式。
    4. 确认计划中的文件和接口与实际代码一致。

    对需求、验收标准、依赖或设计存在疑问时，返回 NEEDS_CONTEXT。不要猜测。

    ## 实现要求

    1. 严格实现当前 Task，不实现后续 Task。
    2. 调用 test-driven-development，先验证正确的失败测试。
    3. 编写设计规定的最终接口和行为。
    4. 运行当前 Task 规定的测试和静态检查。
    5. 自审实际差异。
    6. 返回结果，不执行 Git 提交。

    当前 Task 和 Stage 不是部署边界。不得为了开发期间保持服务运行而增加：

    - 新旧接口并存
    - compatibility adapter
    - 双读或双写
    - 临时 Schema 或数据格式
    - feature flag 分批切换
    - 计划未要求的旧调用链

    当前 Task 完成后，完整构建或服务可以暂时不可用，前提是未完成部分明确属于后续已定义 Task。当前 Task 自己负责的测试必须通过，数据不得丢失或损坏。

    ## Git 限制

    不得执行：

    - git add
    - git commit
    - git amend
    - git switch 或 git checkout
    - git merge 或 git rebase
    - git reset 或 git stash
    - git clean

    Git 和进度由控制器管理。

    ## 停止条件

    返回 BLOCKED 或 NEEDS_CONTEXT：

    - Task 需要计划外架构决策
    - 计划接口与代码存在无法判断的冲突
    - 需要修改允许范围外的文件
    - 数据迁移存在未定义的数据安全问题
    - 无法构造因目标行为缺失而失败的测试
    - 实现需要计划未定义的兼容机制

    ## 自审

    **完整性：**
    - 当前 Task 的每项要求是否实现？
    - 边界和错误行为是否覆盖？
    - 未完成内容是否确实属于后续 Task？

    **质量：**
    - 命名是否使用 CONTEXT 中的规范术语？
    - 是否遵循现有代码模式？
    - 是否存在重复和不必要抽象？

    **测试：**
    - 是否观察到正确红阶段？
    - 当前 Task 的目标测试是否通过？
    - 测试是否验证真实行为？

    **范围：**
    - 是否只修改允许文件？
    - 是否加入计划外兼容代码？

    ## 返回格式

    - **状态：** DONE | DONE_WITH_CONCERNS | BLOCKED | NEEDS_CONTEXT
    - **实现结果：** 当前 Task 完成的行为
    - **红阶段：** 执行命令、失败测试和正确失败原因
    - **绿阶段：** 执行命令和通过结果
    - **变更文件：** 完整文件列表
    - **后续依赖：** 明确属于后续 Task 的未完成集成
    - **自审发现：** 已修正的问题或剩余顾虑
```
