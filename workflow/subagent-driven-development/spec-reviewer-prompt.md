# 规格审查者提示词模板

规格审查先于代码质量审查，验证当前 Task 实现了要求内容且没有增加计划外行为。

```text
分派规格审查子代理：
  description: "审查 Task N 的规格一致性"
  prompt: |
    你正在审查 Task N 的实际实现是否符合计划和最终设计。

    ## 输入

    **Task 完整说明：** [计划中的完整 Task 正文]
    **Stage 设计：** [相关设计章节]
    **完整需求：** [相关成功标准和明确排除]
    **后续 Task：** [用于判断哪些集成确实被后续计划覆盖]
    **实现者报告：** [实现者返回内容]
    **Task BASE_SHA：** [Task 开始前 SHA]

    ## 独立验证

    不信任实现者报告。读取实际代码、测试和工作区差异：

    - `git status --short`
    - `git diff BASE_SHA`
    - 状态中列出的新增未跟踪文件

    ## 检查内容

    ### 缺失要求

    - 当前 Task 的每项要求是否实现？
    - 计划规定的测试、边界和错误行为是否存在？
    - 实现者声称完成但代码中缺失的内容有哪些？

    ### 多余内容

    - 是否实现后续 Task 的职责？
    - 是否增加最终需求未要求的功能？
    - 是否存在过度抽象？

    ### 最终状态设计

    - 当前实现是否使用设计定义的最终接口和命名？
    - 是否误解 Stage 在最终系统中的职责？
    - 是否偏离 CONTEXT 术语？

    ### 开发期兼容机制

    除非最终设计明确要求长期兼容，否则以下内容属于多余实现：

    - 新旧接口并存
    - compatibility adapter
    - 双读或双写
    - 临时 Schema 或数据格式
    - feature flag 分批迁移
    - 为中间服务运行保留的旧调用链

    不得因为当前 Task 无法完整构建、服务无法启动或旧调用方暂时不可用而判定不合规。只有当前 Task 自身职责缺失，或未完成内容没有后续 Task 承担时，才构成问题。

    ### 数据安全

    - 当前修改是否可能丢失、重复或错误转换数据？
    - 计划规定的数据保护是否实现？

    ## 输出格式

    - **状态：** SPEC_COMPLIANT | NEEDS_CHANGES
    - **缺失内容：** [文件和行号]
    - **多余内容：** [文件和行号]
    - **设计偏差：** [文件和行号]
    - **数据安全问题：** [文件和行号]
```
