# Stage 审查者提示词模板

在当前 Stage 的全部 Task 提交后使用。Stage 审查不要求中间服务可部署。

```text
分派 Stage 审查子代理：
  description: "审查 Stage N 的整体实现"
  prompt: |
    你正在审查 Stage N 的整体实现。每个 Task 已通过规格和质量审查。

    ## 输入

    **需求索引：** [brainstorming 文件]
    **Stage 设计：** [当前 Stage 设计文件]
    **Stage 计划：** [当前 Stage 计划文件]
    **前后 Stage 契约：** [相关设计章节]
    **STAGE_BASE_SHA：** [Stage 开始前 SHA]
    **HEAD_SHA：** [当前开发分支 SHA]

    ## 审查范围

    阅读 `STAGE_BASE_SHA..HEAD_SHA` 的完整差异和当前代码。不要信任计划进度或实现者报告。

    ## 检查内容

    ### Stage 设计覆盖

    - 当前 Stage 的每项职责是否完成？
    - 计划中的 Task 是否全部有实际实现？
    - 是否遗漏设计规定的接口、数据、错误处理或测试？

    ### Task 间集成

    - 各 Task 建立的接口和数据结构是否一致？
    - 是否存在断开的调用关系或重复职责？
    - 当前 Stage 是否为后续 Stage 提供约定产物？

    ### 最终状态方向

    - 当前实现是否朝全部 Stage 完成后的最终架构推进？
    - 是否引入设计未要求的新旧接口并存、adapter、双读双写、临时 Schema、feature flag 迁移或旧调用链？
    - 是否存在本 Stage 本应删除的旧实现？

    ### 数据安全

    - 当前 Stage 是否可能丢失、重复或错误转换数据？
    - 设计规定的数据保护是否实现？

    ## 不属于问题的状态

    当前 Stage 不是部署边界。以下情况本身不构成问题：

    - 完整构建暂时失败
    - 服务暂时无法启动
    - 后续 Stage 负责的调用方尚未迁移
    - 旧接口已删除而后续模块尚未更新

    只有本 Stage 自身职责未完成、后续计划没有承担剩余工作或存在数据风险时，才要求修改。

    ## 输出格式

    - **设计覆盖：** [当前 Stage 职责完成情况]
    - **集成状态：** [Task 间接口和数据情况]
    - **后续契约：** [提供给后续 Stage 的产物]
    - **问题：** [按严重、重要、次要分类并附文件和行号]
    - **评估：** APPROVED | NEEDS_CHANGES
```
