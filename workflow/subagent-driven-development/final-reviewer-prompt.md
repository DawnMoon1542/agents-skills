# 最终审查者提示词模板

在最后一个 Stage 合并前使用，审查全部 Stage 的最终集成和完整验证结果。

```text
分派最终审查子代理：
  description: "审查完整需求的最终实现"
  prompt: |
    你正在审查全部 Stage 完成后的最终系统。单 Task 和 Stage 审查已经通过，现在验证完整需求、跨 Stage 集成和最终可用性。

    ## 输入

    **需求索引：** [brainstorming 文件]
    **全部设计：** [按顺序列出 Stage 设计文件]
    **全部计划：** [按顺序列出 Stage 计划文件]
    **术语表：** [CONTEXT 文件]
    **IMPLEMENTATION_BASE_SHA：** [初始文档提交后的 SHA]
    **HEAD_SHA：** [开发分支最终 SHA]
    **完整验证结果：** [构建、类型检查、lint、单元测试和集成测试]

    ## 审查范围

    阅读 `IMPLEMENTATION_BASE_SHA..HEAD_SHA` 的全部差异和最终代码。不要信任 Task 报告或进度标记。

    ## 检查内容

    ### 完整需求

    - brainstorming 中每项成功标准是否满足？
    - 明确排除的功能是否没有实现？
    - 全部 Stage 职责是否完成？

    ### 跨 Stage 集成

    - 组件接口、数据结构和错误类型是否一致？
    - 数据流是否符合全部设计？
    - 是否存在隐式依赖、断开的调用链或未迁移调用方？

    ### 最终架构

    - 实现是否符合设计的最终结构？
    - 术语是否与 CONTEXT 一致？
    - 旧实现、临时接口和过渡代码是否清除？
    - 是否仍存在仅供开发中间状态使用的兼容层？

    ### 数据安全

    - 数据迁移和最终约束是否正确？
    - 是否可能丢失、重复或错误转换数据？
    - 不可逆操作是否有设计规定的保护？

    ### 完整验证

    - 构建是否通过？
    - 类型检查是否通过？
    - lint 是否通过？
    - 单元测试是否通过？
    - 集成测试是否通过？
    - 项目未配置的验证项是否有代码库证据？

    最终审查不允许保留中间失败。服务必须达到完整需求定义的最终可用状态。

    ## 校准

    单 Task 代码质量已经审查。专注于跨 Task、跨 Stage、最终成功标准、数据安全和完整验证。不要重复报告未修改的既有问题。

    ## 输出格式

    - **需求状态：** [成功标准覆盖情况]
    - **集成状态：** [跨 Stage 交互情况]
    - **架构状态：** [最终设计一致性]
    - **验证状态：** [完整命令结果]
    - **问题：** [按严重、重要、次要分类并附文件和行号]
    - **评估：** APPROVED | NEEDS_CHANGES
```
