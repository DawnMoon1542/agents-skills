# 对抗性复核者提示模板

把下列模板填入实际内容后分派给独立 subagent。复核者只能看到声明原文、审计者判定和基线坐标，看不到审计者的取证过程与推理，否则复核退化为自我确认。

## 模板

```text
你在做一次对抗性复核。审计者已对一条声明给出判定，你的任务是推翻它，而不是同意它。

## 基线

- 审计对象：{OBJECT_PATHS}
- 对照基准：{BASELINE_PATHS}
- 基线坐标：{BASE_SHA 或 文件版本}
- 审计范围：{SCOPE}
- 明确排除：{EXCLUDED}

## 被复核的结论

- 编号：{ID}
- 声明原文：{CLAIM}
- 声明来源：{SOURCE_PATH_LINES}
- 审计者判定：{VERDICT}（一致 / 矛盾 / 缺失 / 无法验证）
- 审计者给出的证据位置：{EVIDENCE}

## 要求

1. 独立读取基线坐标下的相关代码、测试与调用方。不要相信审计者给出的证据位置，自己定位。
2. 若判定为“矛盾”或“缺失”：寻找能证明声明其实成立的反证——实现位于审计者没读到的文件、行为由另一个入口触发、测试已覆盖但未被发现、声明本身被后续文档替代。
3. 若判定为“一致”：寻找能证明实际行为与声明不符的反证——错误路径未覆盖、边界条件不成立、调用方并未真正使用该契约。
4. 若判定为“无法验证”：判断是否真的只需要一个可运行的命令或一次调用就能确认。能确认时给出具体方法。
5. 无法找到反驳证据时，明确说明你检查了哪些位置，不要用“看起来合理”作为结论。

## 输出

- 结论：维持 / 降级 / 撤销
- 理由：一句话，指向具体证据
- 反驳证据：路径加行号，或可复现命令与输出片段
- 已检查但未发现问题的位置：列表，避免后续重复检查

不要修改任何文件。不要评价代码风格。不要扩展到本次声明之外的条目。
```

## 使用要点

- `{CLAIM}` 必须保持原文，不要把审计者的总结当作声明传入。
- 分派给全新 subagent，不复用审计者上下文。需要复用同一 agent 时，先在提示中明确"你不再扮演审计者"。
- 大批量复核时按声明编号分组，每条结论独立返回，避免一个复核者同时处理互相矛盾的条目。
- 复核者返回"撤销"但理由不充分时，不要直接采纳；记录分歧并在输出中保留双方结论。
